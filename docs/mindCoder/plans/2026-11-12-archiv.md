# Archiv und persönliche Postfächer — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use mindCoder:subagent-driven-development (recommended) or mindCoder:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Events und Eventanfragen lassen sich umkehrbar archivieren, und Anfragen laufen über persönliche Postfächer (Eingang → Weiterleiten → Postfach → Event anlegen → Archiv).

**Architecture:** Rein additive, optionale Felder im JSON-Store (`_archived` im Event-Override-Store, `archivedAt` im `EventRequestRecord`). Eine zentrale Regel `isEventArchived()` in `events.ts` wird von Liste, Detail und Dashboard genutzt. Die Postfach-Sichten filtert der Server (`?view=`), der Client zeigt nur noch an.

**Tech Stack:** Hono + Zod (API), React + TanStack Query + react-i18next (Web), Vitest, Biome, pnpm.

Spec: `docs/mindCoder/specs/2026-11-10-archiv-design.md`

## Global Constraints

- **Live-Daten nicht anfassen:** Feelgood-Event, Anfrage „YPP Revival“ (Vanessa) und Event „5-jähriges Jubiläum“ (Saskia Rüter) müssen nach dem Deploy unverändert erscheinen.
- Kein Schema- oder Datenmigrations-Skript. Kein Löschen. Archivieren ist jederzeit umkehrbar.
- Fehlt `_archived` bzw. `archivedAt`, gilt der Datensatz als **nicht archiviert** (Ausnahme: OneNote-Events, siehe Task 1).
- Postgres-Pfad (`DATABASE_URL` gesetzt) bleibt unverändert; neue Archiv-Routen antworten dort mit 501.
- Fehlerformat: `{ error: { code, message } }`; 404 für unbekannte ID, 403 bei fehlender Rolle; erneutes (De-)Archivieren ist idempotent (200).
- Alle UI-Texte in `apps/web/src/locales/de.json` **und** `en.json`.
- Vor jedem Push: Biome-Check im LF-Klon (siehe Task 6), da lokales CRLF echte Fehler verdeckt.
- Tests laufen aus dem Repo-Root: `pnpm vitest run <pfad>`.

/**
 * Zentrale Archiv-Regel (Spec 2026-11-10-archiv-design.md §1).
 * - Override `_archived: true/false` gewinnt immer.
 * - Fehlt das Feld: OneNote-Termine gelten als archiviert, alles andere als aktiv.
 *   So bleiben Live-Events ohne jede Datenänderung sichtbar.
 */
export function isEventArchived(
  eventId: string,
  override: Record<string, unknown> | undefined,
): boolean {
  const flag = override?._archived;
  if (flag === true) return true;
  if (flag === false) return false;
  return isOneNoteEventId(eventId);
}

- [ ] **Step 5: Archiv-Routen**

Direkt vor `eventRoutes.delete("/:id", ...` einfügen:

```ts
// Archiv (Spec 2026-11-10-archiv-design.md §1): nur Admin, umkehrbar, idempotent.
// Schreibt ausschließlich das Override-Feld `_archived`, alle anderen Felder bleiben.
function setEventArchived(c: Context, archived: boolean) {
  if (env.DATABASE_URL) {
    return c.json(
      { error: { code: "NOT_SUPPORTED", message: "Archiv nur im Datei-Modus." } },
      501,
    );
  }
  const id = c.req.param("id");
  const base = findDevBaseEvent(id);
  const current = devEventOverrideStore.get(id) ?? {};
  if (!base || current._deleted === true) {
    return c.json({ error: { code: "NOT_FOUND", message: "Event nicht gefunden" } }, 404);
  }
  devEventOverrideStore.set(id, { ...current, _archived: archived });
  return c.json({ event: { ...applyOverride(base), archived: isEventArchived(id, { _archived: archived }) } });
}

eventRoutes.post("/:id/archive", requireMexpRole("admin"), (c) => setEventArchived(c, true));
eventRoutes.post("/:id/unarchive", requireMexpRole("admin"), (c) => setEventArchived(c, false));
```
